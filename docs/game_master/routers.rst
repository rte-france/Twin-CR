Routers
=======

The FastAPI routers under ``gamemaster.core.routers`` expose HTTP endpoints
that orchestrate DSL ingestion, simulator stepping, IIDM management, and user
controls. This chapter provides both narrative descriptions and autogenerated
API signatures for each router module.

Trainer Router (``/trainer``)
-----------------------------

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - Endpoint
     - Description
   * - ``POST /trainer/dsl_command``
     - Parse ad-hoc DSL commands provided by a trainer and enqueue them in the
       event store for the active simulation.
   * - ``POST /trainer/init``
     - Upload (or reuse) IIDM artifacts, parse DSL from the ClickHouse-backed
       storage or an uploaded file, and return a ``SimulationConfig`` describing
       the initialized scenario.
   * - ``GET /trainer/dsl/simulations``
     - List stored DSL files (with friendly names, storage object paths, and
       metadata).
   * - ``GET /trainer/iidm``
     - List IIDM artifacts along with cached metadata, upload timestamps, and
       related files.
   * - ``GET /trainer/dsl/{simulationName}``
     - Download the DSL script for ``simulationName`` as plain text.
   * - ``DELETE /trainer/dsl/{simulationName}``
     - Remove the DSL script associated with ``simulationName`` from storage.
   * - ``PUT /trainer/dsl/{simulationName}``
     - Upload or replace the DSL script for ``simulationName`` using the request body.

User Control Router (``/user``)
-------------------------------

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - Endpoint
     - Description
   * - ``PUT /user/control``
     - Enqueue an individual control request from a user (load, generator,
       switch, etc.).
   * - ``PUT /user/cluster_control``
     - Validate static lists or dynamic cluster definitions and expand them
       into per-target controls.
   * - ``GET /user/controls``
     - Preview controls scheduled for the next simulator step.
   * - ``GET /user/status``
     - Return the GameMaster service status payload, including simulator readiness.

Queue Router (``/queue``)
-------------------------

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - Endpoint
     - Description
   * - ``GET /queue/list``
     - Paginate through stored events with optional filters such as status,
       source, or simulation name.
   * - ``PUT /queue/{event_id}``
     - Modify a DSL/trainer event in-place (validate DSL, preserve id, enforce timing/time_spec guards).
   * - ``DELETE /queue/{event_id}``
     - Delete a DSL or trainer event by id when it is still pending/scheduled/active.
   * - ``GET /queue/summary``
     - Provide per-status counts (pending, scheduled, active, etc.) for quick monitoring.

Logs Router (``/logs``)
-----------------------

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - Endpoint
     - Description
   * - ``GET /logs/simulations``
     - List simulations that have DSL execution log entries with first/last timestamps.
   * - ``GET /logs/sim/timeline/{simulation}``
     - Return the base DSL plus append/execution timeline for a simulation.
   * - ``GET /logs/sim/timeline/{simulation}/raw``
     - Reconstruct the DSL script (base + appends) as plain text for the simulation.
